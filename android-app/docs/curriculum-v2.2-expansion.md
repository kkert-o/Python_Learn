## 与总纲的对应关系

总纲描述了从编程基础到综合工程的完整路线。本轮先把主骨架补齐，并做两项工程化收敛：

1. 总纲中的“阶段 0 编程与计算机基础”纳入正式第一阶段，后续按 1 至 16 编号。
2. OOP、异常、FastAPI、数据库和 AI 暂时保留在已有阶段，后续继续拆分和加深，不通过一次性大规模重排破坏已有进度键。

## 后续扩展顺序

### 第二轮：Python 进阶与网络基础

- 类型提示
- dataclass
- 装饰器与闭包
- 生成器与迭代器
- 上下文管理器
- IP、DNS、TCP、UDP 和端口
- HTTP 方法、状态码、Header、Cookie、Session 和 HTTPS
- requests、httpx 和异步请求对比

### 第三轮：爬虫、数据与自动化纵深

- HTML、CSS Selector、XPath 和 DOM
- Playwright、Selenium 和 Scrapy
- 重试、超时、限速、分页和断点恢复
- pandas 清洗、分组、合并、缺失值和可视化选择
- MySQL、PostgreSQL、Redis 和 SQLAlchemy
- Excel、浏览器、桌面和定时自动化

### 第四轮：Web、AI 与工程质量

- Flask 到 FastAPI、Django 的框架选择
- 认证、授权、Token、部署、监控和回滚
- 机器学习、PyTorch、Transformers、Embedding、RAG 和 Agent
- pytest 参数化、Mock、日志、配置和持续集成
- 第三方库版本、许可证、漏洞与供应链风险

### 第五轮：练习和项目联动

每个新增知识点都需要逐步补齐：

```text
内容知识点
↓
课程小练习
↓
专项训练
↓
错误博物馆
↓
项目任务
↓
复习与能力评价
```

不能只增加正文数量。没有练习、错误训练和项目迁移的知识点，不算完整扩展。

## 内容维护规则

- 保留已有知识点 ID，避免用户进度失效。
- 调整课程顺序时，必须重新检查 `next` 跳转。
- 新知识点必须出现在一个真实阶段中，且 `LessonDetail.stage` 与阶段名称一致。
- 内容版本变化后，必须通过 JSON 解析、内容校验和单元测试。
- 同一轮扩展优先覆盖完整能力闭环，不先大量加入无法运行或无法验证的标题。
